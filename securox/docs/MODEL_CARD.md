## 1. Model Overview

Securox employs a multi-model hybrid AI architecture designed to overcome the individual limitations of standalone unsupervised anomaly detectors and supervised pattern classifiers:

```
Telemetry Event --> [Feature Engineering Pipeline] (12-Feature Scaled Vector)
                         |
       +-----------------+-----------------+
       |                                   |
[Model A: Isolation Forest]     [Model B: XGBoost Classifier]
(Unsupervised Anomaly Score)   (9-Class Attack Categorization)
       |                                   |
       +-----------------+-----------------+
                         |
      [Model C: DBSCAN Entity Tracking] (Behavioral Clusters)
                         |
      [Risk Intelligence Engine] (Configurable 0-100 Composite Score)
                         |
      [SHAP & Deviation XAI Engine] (Human-Readable Explainability)
```

### Component Models:
1. **Model A: Unsupervised Anomaly Detection (`IsolationForest`)**
   - **Framework**: `scikit-learn` 1.8.0
   - **Configuration**: 150 estimators, `max_samples='auto'`, `contamination='auto'`, fitted exclusively on legitimate/benign network flows.
   - **Function**: Produces continuous `anomaly_score` (0.0 to 1.0) sensitive to zero-day and novel deviations without relying on attack signatures.
2. **Model B: Supervised Multi-Class Classifier (`XGBoost`)**
   - **Framework**: `xgboost` 3.3.0
   - **Configuration**: Gradient boosted trees (`objective='multi:softprob'`, `max_depth=6`, `learning_rate=0.1`, `n_estimators=100`).
   - **Function**: Categorizes flow events into 9 canonical classes: `BENIGN`, `DDOS`, `DOS`, `PORT_SCAN`, `BRUTE_FORCE`, `BOTNET`, `INFILTRATION`, `WEB_ATTACK`, `OTHER`.
3. **Model C: Behavioral Entity Clustering (`DBSCAN`)**
   - **Framework**: `scikit-learn` 1.8.0
   - **Configuration**: `eps=1.2`, `min_samples=5`.
   - **Function**: Clusters rolling IP and device entity profiles to identify botnet swarm behavior and distributed entity outliers.
4. **Model D: Explainable AI (`SHAP` & Deviation Surrogates)**
   - **Framework**: `shap` 0.52.0 `TreeExplainer`
   - **Function**: Calculates exact Shapley additive feature attributions for every classified alert, answering: *"Why is this high risk?"*

## 2. Intended Use & Scope

* **Primary Application**: Autonomous real-time threat detection and cascading risk quantification across smart-city digital infrastructure (Power Grid, Traffic Control, Municipal Water SCADA, Healthcare, Citizen Portals).
* **Target Users**: Municipal Security Operations Center (SOC) analysts, city infrastructure engineers, cyber-physical incident response commanders.
* **Out-of-Scope Use**: Should not be used as an unconditional, automated network kill-switch for life-critical healthcare equipment without human-in-the-loop operator confirmation.

## 3. Training & Validation Datasets

Securox is trained and benchmarked across four globally recognized cybersecurity datasets, converted into the Securox Canonical Telemetry Schema:

| Dataset | Provider / Citation | Records Sampled | Normalization Strategy |
| :--- | :--- | :--- | :--- |
| **CICIDS2017** | Canadian Institute for Cybersecurity (UNB) | 15,000 flows | Mapped flow duration, packet rates, byte rates, ports |
| **UNSW-NB15** | Cyber Range Lab, UNSW Canberra | 15,000 flows | Normalized packet metrics, session durations, protocols |
| **TON_IoT** | UNSW Canberra IoT Cyber Range | 10,000 flows | Mapped SCADA/MQTT IoT device telemetry |
| **NSL-KDD** | University of New Brunswick | 25,192 flows | Mapped host connection frequencies, error ratios |

### Data Splitting & Leakage Prevention
* **Splits**: 70% Training / 10% Validation / 20% Test (Stratified by attack class).
* **Zero Leakage**: Feature scalers (`StandardScaler`) are strictly fitted on the training split only and persisted via `models/feature_scaler.joblib`. Rare classes (< 5 occurrences) are cleanly pruned prior to stratification to prevent single-sample test contamination.

## 5. Cross-Dataset Generalization (Domain Shift Analysis)

To evaluate real-world robustness against distribution shifts, a model trained strictly on **CICIDS2017** was tested against **UNSW-NB15** records without retraining:

* **Observation**: Supervised classification accuracy experiences domain degradation when feature distributions (e.g. protocol packet sizing) differ across network topologies.
* **Securox Defense Strategy**: When supervised confidence drops below 0.60 or domain shift is identified, Securox automatically elevates the weight of the **Unsupervised Isolation Forest** anomaly score and **Threat Intelligence IOC matches**, ensuring zero-day attacks do not evade detection. Full details are documented in `reports/CROSS_DATASET_EVALUATION.md`.

## 6. Explainable AI (XAI) Architecture

Every high-risk event flagged by Securox is augmented with human-interpretable feature attributions:
* **Top Drivers**: Explicit feature contributions calculated via SHAP TreeExplainer (e.g., `Inbound Request Velocity: +42%`, `Bandwidth Consumption: +31%`, `Connection Reset Ratio: +22%`).
* **Deviation Factors**: Multipliers relative to nominal baseline (e.g., `112.0x higher than nominal traffic baseline`).
* **Plain-English Reasons**: Concrete statements highlighting affected critical infrastructure nodes, cascading propagation risks, and threat intelligence matches.
* **Safe Directives**: Actionable, non-destructive mitigations (e.g., ingress rate-limiting, edge cryptographic validation).

## 7. Limitations & Ethical Considerations

1. **Encrypted Payloads**: Securox inspects network flow metadata, IP packet headers, and timing metrics without performing SSL/TLS deep packet decryption, preserving citizen data privacy while identifying volumetric and behavioural anomalies.
2. **Adversarial Perturbations**: Sophisticated adversaries may attempt low-and-slow probing to remain below anomaly thresholds. Securox counters this via multi-horizon temporal tracking and DBSCAN clustering.
3. **Fail-Safe Operation**: Securox response recommendations default to non-destructive isolation (rate-limiting and VLAN segmentation) to prevent unintentional disruption of municipal public services.
